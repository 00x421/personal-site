fix(content): 修掉 /now 的技术栈事实错误，并让搜索建议词从索引推导

盘点内容时发现两个挂在线上、关于站点自身的问题。两个都不是这轮引入的。

一、/now 写着本站是「Cloudflare Workers 边缘部署」（事实错误）
实际是腾讯云自托管：nginx 直服静态资源 + systemd 托管 Node 进程，
README 里也明确写着 Workers「当前未使用」。那句话是迁移前的方案残留。

这类错误对「同行 / 技术朋友」读者伤害最大——他们恰好会看技术细节，
而一个关于自己站点的错误陈述比没有陈述更糟。
已改为「自托管 Node（nginx + systemd）」，并加注释说明为什么别再写回边缘部署。

二、搜索面板 4 个建议词里有 3 个点了搜不到东西
建议词原为 ['工程手记','Cloudflare','闭环','提示词']，都是内容还是 AI 占位
阶段的词。占位内容撤下后实测命中：

  工程手记   1 条
  Cloudflare 0 条   <- 站点根本不用 Cloudflare
  闭环       0 条
  提示词     0 条

访客点「闭环」看到的是「没找到相关的内容」。而「闭环」「提示词」本身就是
AI 味最重的词。

改成从索引实时推导出现次数最多的文章 / 项目标签（topTags），
于是这件事在结构上不会再发生：标签既然出现在某条索引里，就必然有命中。
书架的状态标签（在读）不参与——把「在读」当搜索词没意义。

实测建议词变为 前端(3) / 调试(2) / 工程实践(2) / 架构(2)，逐个点击均有结果。

验证：npm test 76/76、tsc 零错误、oxlint 零告警；线上 /now 已无
Cloudflare/Workers/边缘 字样，搜索面板建议词为上述四项且都能搜到。
